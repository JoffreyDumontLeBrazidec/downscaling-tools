# Proposed changes to AGENTS.md and CLAUDE.md, 2026-09-28

This file proposes edits to `AGENTS.md` and `CLAUDE.md`. It does not apply them,
because those two files are the rules an agent reads first and a person should decide
what goes into them. Each proposal says what to change, gives the replacement text,
and says why.

## What changed in the repository that these files do not yet say

1. `eval/cli.py` is now the package `eval/cli/`, with one module per command. The
   command line is unchanged, but agents that look for the code of a command now find it
   in `eval/cli/<command>.py`.
2. Two discovery commands exist: `python -m eval.cli list` prints every evaluator and
   `python -m eval.cli describe <evaluator>` explains one. They read the registry and the
   evaluator packages, so they are always current.
3. Every evaluator package follows one written contract, `eval/evaluators/base.py`, and a
   test (`eval/tests/test_evaluator_contract.py`) checks it.
4. `python -m pytest` at the repository root now collects every test folder, and it ends
   with no failing test: everything that was red on 2026-09-28 was fixed, moved to the
   quarantine, or marked xfail with a reason. `TESTING.md` has the table.
5. `README.md` is now the entry page, with a directory map and a five-command quickstart.
6. `.gitignore` now covers `/graphify-out/`, `/mlflow/` and core dumps. `AGENTS.md`
   already says `graphify-out/` is git-ignored, but until now it was not.

## Proposed edits to AGENTS.md

### 1. "Start here": add the README and the discovery commands

Replace the first bullet list with:

```markdown
## Start here

- **`README.md`** — what the repository is, a directory map, and a five-command quickstart.
- **`python -m eval.cli list`** and **`python -m eval.cli describe <evaluator>`** — what can
  be evaluated and how each evaluator works. Generated from the registry, so never stale.
- **`ARCHITECTURE.md`** — the stack map and the four independent resolution lanes.
- **`eval/README.md`** — the evaluation harness (`eval.cli`), and the lane-retirement convention.
- **`eval/config/lanes/README.md`** — how `base:` inheritance works and why the generated
  `_ladder_*` files are not tracked.
- **Decisions, open work and prior verdicts live in `~/dev/docs`** on hpc-login — a separate
  repo, not vendored here. Its `AGENTS.md` owns the session reading order. This repo is code;
  that repo is the record.
```

Why: an agent that starts from the README and the two commands reaches the right evaluator
without reading the registry file or grepping.

### 2. "Tests": the suite is no longer red

Replace the paragraph that begins "Note: a number of tests currently fail" with:

```markdown
`python -m pytest` at the repository root collects every test folder. It should end with
no failing test. A test that is expected not to pass is marked `xfail` with a reason, and
`TESTING.md` lists each one. If a test fails, you probably broke it: compare with the
merge base only if the test is not in that list. The legacy ds tests
(`manual_inference_legacy_ds/tests/`) run in a subprocess, because that tree must be
installed under the name `manual_inference`.
```

Why: the old note taught agents to ignore red tests. Now that the suite is clean, a red test
carries information again.

### 3. New section "Adding or changing an evaluator"

Add after "House rules":

```markdown
## Adding or changing an evaluator

An evaluator is declared once, in `eval/evaluators/registry.py` (group, question, host
limit), and implemented as a package `eval/evaluators/<name>/` that follows the contract in
`eval/evaluators/base.py`: `run`, `score`, `plot` and `EVALUATOR_SPEC` (with `outputs`).
Use `no_score` and `no_plot` for what the evaluator does not have. Run
`python -m pytest eval/tests/test_evaluator_contract.py eval/tests/test_evaluator_registry.py`
and `python -m eval.cli describe <name>`. To retire one, move its package to
`eval/_quarantine/<date>/` and change its registry entry to `retired`.
```

Why: this is the procedure that was previously spread over three files.

### 4. "Optional: graphify knowledge graph"

No change needed. The statement that `graphify-out/` is git-ignored is now true.

## Proposed edits to CLAUDE.md

`CLAUDE.md` is not tracked. It is excluded through `.git/info/exclude` on the live
checkout, and it contains an unfinished "SPECKIT" block (the sentence "read the current
plan" stops in the middle) followed by a graphify block. The repository already has
`AGENTS.md` as the shared entry point, and the user's global instructions say that the
Claude Code, Codex and Copilot files should be one file. The proposal is to replace
`CLAUDE.md` with this, and to keep it untracked:

```markdown
Read `AGENTS.md` in this directory first; it is the shared entry point for every agent.
For codebase questions, use `python -m eval.cli list` and `describe <evaluator>` before
grepping, and the graphify graph in `graphify-out/` when it exists (`graphify query "<question>"`).
```

Why: it removes the broken block and the duplicated graphify instructions, and it stops
`CLAUDE.md` and `AGENTS.md` from drifting apart.
